This skill is the entry point and router. It produces one short written assessment — what agentic infrastructure already exists for this person and/or this project, each finding honestly labeled **enforced** or **asserted** or **missing**, followed by exactly one recommended next skill (or a short ordered list, when more than one gap is real).

## Procedure

1. **Fix scope.** Decide whether this run is about a person, a project, or both. Most sessions are both, because a project is worked on by a person.

2. **Inventory the user profile.** Look for a user-criteria collection (`INDEX.yaml`, `criteria/<category>/`, `harness/bindings.yaml`, `CHANGELOG.md` — see [profiles/user/02-collection.md](${CLAUDE_PLUGIN_ROOT}/profiles/user/02-collection.md)). If found, note its size against the collection's own health signals: under ten active criteria after months of use means corrections aren't being captured; over a hundred means it's absorbing facts a generator will never select. If absent, that is a missing input, not an error.

3. **Inventory the project profile.** Look for `project-profiles/{project-id}/facts/<category>/`, `harness/bindings.yaml`, `practices.yaml`, and the cross-project `INDEX.yaml` (see [profiles/project/02-collection.md](${CLAUDE_PLUGIN_ROOT}/profiles/project/02-collection.md)). Note `oldest_verification` if the index exists — a profile whose least-recently-verified fact is months old is trusted further than its evidence supports. Note whether `capability` facts exist at all; their absence means every enforcement question downstream defaults to "unknown," which the loop treats as absent.

4. **Inventory adopted practices.** Look for `adoption/{practice-id}/practice-manifest.json` for any practice-id, and for entries in the project profile's `practices.yaml`. For each manifest found, read its `phase` (`draft | apply | live | retired`) — a manifest stuck in `draft` or `apply` is an interrupted run, not a live practice. Do not run drift detection here; that is [/magentix:check-practice-drift](../check-practice-drift/SKILL.md)'s job. Just note what exists and its phase.

5. **Inventory agent-tooling files actually on disk**, independent of whether a profile mentions them: a global always-loaded file (e.g. `~/.claude/CLAUDE.md`), a project-level file (`CLAUDE.md` / `AGENTS.md`), the contents of `.claude/` (skills, hooks, `settings.json`), and any CI configuration invoking a validator named in a spec tree or a practice manifest. A file that exists but was never generated by anything in this collection is worth noting as unaccounted-for, not silently absorbed into the assessment.

6. **Classify every finding as enforced or asserted, never both.** Per [the third invariant](${CLAUDE_PLUGIN_ROOT}/adoption/01-loop.md): **enforced** means it fails closed and you can name the mechanism (a hook, a required check, branch protection with no bypass); **asserted** means it is a document someone is asked to honor and nothing checks it. A control you cannot name a failing-closed mechanism for is asserted, however confidently it is labeled elsewhere. A template file with its placeholders still intact is neither — it is unfilled, and reads as a prior failed adoption, not as coverage.

7. **Report honestly what is missing.** Say plainly when a scope has nothing — no profile, no practice, no tooling file — rather than describing an empty state in hedged language. Missing is a legitimate, common finding.

8. **Route to exactly one next move**, using the table below, and state the adoption ordering advice that governs the recommendation:
   - **Profile before practice.** A practice compiled against a thin or absent profile is a practice built on guesses. If there is no profile, or the existing one is thin, that is the recommendation — not the practice.
   - **Minimum viable subset before the full blueprint.** Every blueprint in this repo names one (the Agent Context Kit's four files are themselves the minimum; the AI-SDLC's is its six-artifact spec). Recommend starting there, never the whole blueprint at once.
   - **One practice at a time.** Never recommend adopting two blueprints in the same pass.

## Routing table

| What the inventory found | Recommend |
|---|---|
| No user-profile collection, or too thin to trust | [/magentix:elicit-user-profile](../elicit-user-profile/SKILL.md) |
| No project profile, or `oldest_verification` badly lapsed | `/magentix:survey-project-profile` |
| Profile(s) exist but the capability inventory is thin, stale, or absent | `/magentix:inventory-capabilities` |
| Harness binding missing, stale, or the tool changed | `/magentix:bind-harness` |
| A profile exists and no practice has been adopted yet, and the person wants the preference layer | [/magentix:setup-agent-context](../setup-agent-context/SKILL.md) — or, for the tracked, gated, re-enterable version, [/magentix:adopt-practice](../adopt-practice/SKILL.md) against the Agent Context Kit blueprint |
| A profile exists and the project wants a spec-driven delivery plane | [/magentix:author-spec-tree](../author-spec-tree/SKILL.md), or [/magentix:adopt-practice](../adopt-practice/SKILL.md) against the AI-SDLC blueprint for the full loop |
| A profile and blueprint are both ready to compile | [/magentix:adopt-practice](../adopt-practice/SKILL.md) |
| A practice manifest exists (`phase: live`) | [/magentix:check-practice-drift](../check-practice-drift/SKILL.md) |
| A manifest is stuck at `phase: draft` or `phase: apply` | [/magentix:adopt-practice](../adopt-practice/SKILL.md) to resume from where it stopped |

Where more than one row applies, order the recommendation by the ordering advice above (profile work before practice work), and present it as a short numbered list rather than a single instruction, but still land on what to do *first*.

## Do not

- Do not classify something as enforced without naming the mechanism that fails closed. If none can be named, it is asserted.
- Do not treat a template with unfilled placeholders as an adopted practice.
- Do not read, merge, or reshape any profile found during the inventory. This skill only reads.
- Do not run spec validation, materialization checks, or drift detection yourself — route to the skill that owns each.
- Do not recommend adopting a practice before a profile exists for the audience that practice's elements are authored by.
- Do not recommend the full blueprint when its own minimum viable subset has not been reached yet.
- Do not recommend adopting more than one practice in the same pass.
- Do not produce a wall of findings. The assessment is a short written report, not an exhaustive audit transcript.

## How to know you did it right

- Every finding is labeled enforced, asserted, or missing — never left ambiguous.
- The report says plainly what is absent, with no hedging.
- Exactly one next move is recommended, or a short ordered list when several gaps are real, and the order follows profile-before-practice.
- Nothing was written to any profile, manifest, or practice file during this run — the skill only inventories.
